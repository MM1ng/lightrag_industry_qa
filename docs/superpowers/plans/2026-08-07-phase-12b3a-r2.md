# Phase 12B-3A-R2 Semantic Judge Output Contract Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stabilize the offline Semantic Judge output contract and measure first-pass protocol reliability without changing semantic definitions, runtime candidates, models, retrieval, or online code.

**Architecture:** Preserve the R1 parser and replay as historical behavior. Add a separate compact-output contract module with strict deterministic validation, a forensic audit artifact for the 26 R1 invalid batches, and an R2 runner that consumes the exact R1 hydrated matrix, calls each batch once, saves raw responses, and applies a protocol gate before semantic scoring.

**Tech Stack:** Python, pytest, existing OpenAI-compatible client, JSON/JSONL artifacts, existing Development-only evaluation files.

## Global Constraints

- Use only the existing Development split and the exact R1 hydrated Runtime candidate matrix.
- Do not read Golden, Validation, Holdout, expected evidence, or Oracle labels during hydration or Judge input construction.
- Do not modify Retrieval, Rerank, Context, Generation, Citation Selector, Grounding, Refusal, Semantic Support definitions, evaluation data, or online Runtime APIs.
- Do not change the model or add SDK dependencies.
- Each R2 batch receives exactly one Judge call; no retry or repair call.
- If Protocol Gate fails, write `OUTPUT_CONTRACT_FAIL` and do not calculate Semantic quality metrics.
