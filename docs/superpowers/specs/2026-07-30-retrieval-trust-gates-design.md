# 检索可信度门控设计

**日期：** 2026-07-30
**状态：** 已确认，待规格审阅

## 背景与目标

在 50 题真实黄金集上，系统已能稳定返回答案和引用，但存在两个可信度问题：所有解析到的候选证据都会作为引用返回，且只要有任意证据就继续生成答案。结果是引用存在率偏高，而两道无依据题均未被可靠拒答。

本轮目标是先提高回答可信度，不追求扩大召回范围：

- 无依据拒答率不低于 90%；
- 引用可追溯率不低于 95%；
- 每个成功回答最多返回 3 条引用。

## 方案

采用确定性“路由 → 门控 → 过滤 → 生成”链路，不增加新的模型调用：

```text
用户问题
  → 文档路由
  → LightRAG 候选证据
  → 证据质量门控
  → Top-3 引用过滤
  → 基于保留证据生成，或固定拒答
```

### 文档路由

维护由现有两份文件名与其稳定别名组成的文档标识词表，例如 `2196`、`SUMMIT`、`DESMI`、`t1739`。问题命中某一份手册的唯一标识时，只保留该文件的候选 Chunk；没有唯一命中时保留跨文档检索结果。路由不会替代 LightRAG 检索，也不会根据生成答案反推来源。

### 证据质量门控

在调用生成模型之前评估候选 Chunk：

1. 不存在可解析、可追溯的引用时，直接拒答；
2. 路由到单份手册后，没有该文件的候选引用时，直接拒答；
3. 候选证据与问题不共享足够的归一化关键词时，直接拒答；
4. 通过门控时，才把过滤后的证据交给生成模型。

关键词规则只使用问题与 Chunk 文本中的中文词、英文词、型号和数字；停用词不参与匹配。阈值以黄金集开发结果显式配置，不根据线上请求自适应变化。拒答沿用 `INSUFFICIENT_EVIDENCE_MESSAGE`，并返回空引用。

### 引用过滤

引用从已通过门控的候选 Chunk 生成，按路由一致性、关键词重合度和原始检索顺序排序；按 `source_file + page_number + chunk_id` 去重后最多保留前三条。生成上下文只能使用这批保留 Chunk，避免答案基于未展示的证据而引用另一批 Chunk。

## 评测与验收

继续使用已验证的 50 题工业泵黄金集，且在报告中新增：

- `average_citations_per_answer` 与 `max_citations_per_answer`；
- `document_route_accuracy`：存在唯一文档标识的问题中，保留引用是否全部属于目标文档；
- 各类拒答结果及误拒答数量。

执行前记录 Kimi K2.6 基线报告；实施后在同一索引、同一模型、同一黄金集上重跑。仅当满足三个目标且成功率不低于当前基线时，视为验收通过。若 Recall@5 比基线降低超过 5 个百分点，则保留门控实现但不默认启用，先复核阈值与黄金标注。

## 范围边界

本轮不增加 Reranker、Ragas、LangGraph、多 Agent、在线学习、会话记忆或新数据库；不改变 PDF 解析、嵌入模型和图谱构建。下一轮在可信度门控稳定后，才考虑检索召回优化。
